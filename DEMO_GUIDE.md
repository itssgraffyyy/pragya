# Five-minute PRAGYA demonstration

## Preparation

Run `npm run build` then `npm run offline`. Open the printed loopback address in a supported desktop browser. Keep that hostname, port and browser profile for persistent records. Start with low graphics and reduced motion in Settings. Wait for Home to report the offline shell ready before disconnecting the network.

In **Units & Identities**, choose **Unrestricted local demo**. Home → **Synthetic Demo** → **Load synthetic demo**. Installation appends a separate labeled synthetic unit, five local identities and three trainee profiles. It preserves existing data and refuses duplicate installation. No network or AI service is required.

The loader scripts actual original-engine decisions and runs the existing scorer, learning services, assignment services and crew runtime. It arranges synthetic calendar dates explicitly; it never writes invented scores, competency values or improvement percentages. Installed records contain:

- Asha: three incorrect, high-confidence recognition baselines; completed tailored practice and a fresh-seed evaluation; the original calibration gap and calculated correction remain traceable. The crew history separately preserves an incorrect private classification corrected in the joint report.
- Biren: three correct recognition baselines, one completed instructor assignment and the shared crew exercise. The consistent recognition cohort is distinct from the ambiguous crew cohort.
- Chitra: no measured history, plus a pending instructor assignment. Missing competencies display as unassessed rather than zero.
- A scoped instructor, commander, foundation cohort, individual feedback, crew feedback, recorded sharing/uncertainty/acknowledgments, separate individual/joint scores and unit-owned outcomes.

The dataset has 11 original-engine individual assessments, one completed crew session and two instructor assignments. Labels identify synthetic data in profile names, reference codes, unit, identities and feedback. These are scripted training examples, not genuine participant performance or readiness evidence.

## Script

**0:00–1:00 — Simulation.** Home → Scenario Selection → Single Contact — Basic Recognition → Begin → Start. Wait for the contact to appear (about five simulation seconds). Select c1, acknowledge it and observe the synthetic shape/feed. Explain that ground truth is hidden during training. For an ambiguity example, choose a bundled uncertain/degraded scenario instead. Abort or finish before returning to demo management.

**1:00–2:00 — Decision intelligence.** Submit a classification, confidence, evidence and fictional response. Open the assessment and the recorded-event replay; inspect the applied decision-tree rule and evidence explanation. Scores and calibration are separate. Bundled policy content is illustrative and needs institution-specific approval.

**2:00–3:00 — Skill DNA.** Home → Synthetic Demo → **View Skill DNA 1**. Open Asha's measured calibration/classification cohort and supporting session IDs. Show the original repeated overconfidence evidence and recommendations in **Open adaptive learning**. Profiles 2 and 3 contrast established recognition evidence with unassessed coverage. Compare within the same policy and observation conditions.

**3:00–4:00 — Personalized improvement.** Home → Synthetic Demo → **View corrected mistake and progress**. Show the saved practice and unseen-evaluation comparisons, their real source IDs and calculated point changes. Explain that both outcomes were executed by the engine using scripted correct decisions. Open adaptive learning to generate a remaining recommended exercise; the original generator reports supported and unsupported controls. Demonstrating a launch does not establish a new improvement result.

**4:00–5:00 — Crew and unit.** Home → Synthetic Demo → **Open demo crew AAR**. Under Saved crew sessions open **Conflicting observations · completed**. Scrub Recorded crew event: identify the private initial error, explicit uncertainty, both shared observations, acknowledgments and confirmed report. Compare coordination with separate individual and joint recognition scores; an appropriate unknown answer can earn partial classification credit under the bundled policy even with excellent coordination. Then Home → Units & Identities → Unrestricted local demo → Home → Synthetic Demo → **Open demo instructor** to show completed/pending assignments and feedback. Return through Unrestricted local demo and use **Open demo unit intelligence** to show all three rows, condition/policy cohorts and unassessed coverage.

Role selection is deliberate: commander summary permission does not grant raw AAR access. Use the demo instructor for scoped review. To return to demo shortcuts from a role view, select Unrestricted local demo in Units & Identities.

## Safe reset and repeat

Finish or abort the current individual exercise and leave any crew host workspace. Export any synthetic training you want to retain. Choose Unrestricted local demo → Synthetic Demo → **Preview demo reset**. Review the exact counts, type `RESET DEMO`, then choose **Reset synthetic demo only**.

Reset removes only the installed demo unit, its original identities/profiles, plans and their sessions/unit records. It also removes further exercises recorded exclusively for those demo participants. It refuses extra unit identities, authored unit scenarios, references from outside records, active crew hosts and data changes after preview. A single atomic transaction compares the current stores before deleting selected keys; it never clears the database. Genuine records and application settings remain; an active demo-profile selection falls back to a remaining genuine profile or the default ID. A changed preview must be refreshed.

Load again to repeat with new identities. If reset refuses, keep the records, export a backup and resolve the stated references or activity; do not clear browser storage to force it.

## Demonstration limits

Single laptop/two participants; browser-local host handover, no LAN synchronization. Synthetic geometry/sensors and event replay, not physical sensing or video. Local role selection is not secure authentication. Coordinated swarms, VR, packaged executables and hardware-fleet qualification remain outside verified delivery. See PS_COMPLIANCE.md and TEST_REPORT.md.

Presentation reliability caveat: the final full browser run needed the existing retry for one original onboarding Start-button timeout; the retry passed. Rehearse and warm the application on the presentation machine, and retain the disclosed cold-start reliability limitation. Do not describe the final browser run as retry-free.

A subsequent full run also needed a retry waiting for a backup download event. The shared JSON download helper now keeps its object URL alive during asynchronous browser initiation; immediate cleanup was a possible race. Host/startup/download responsiveness still needs rehearsal and qualification; the test report retains each flaky result and the post-change verification.
