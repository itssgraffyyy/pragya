# Five-minute PRAGYA Module 5 demonstration

## Preparation

Run `npm ci`, `npm run build`, then `npm run offline`. Open http://localhost:5173 in a desktop browser, choose low graphics/reduced motion, and wait for Home to report offline resources ready. Keep the hostname, port and browser profile unchanged. The prepared app then works with the network disabled. Installing dependencies and browser-test binaries is a development preparation step, not a runtime cloud dependency.

In Units & Identities choose **Unrestricted local demo**. Home → **Synthetic Demo** → **Load synthetic demo**. Existing data remain intact. An older installed Module 4 demo can be kept or reset/reinstalled to obtain the new examples. The current loader creates a separate labeled unit, five identities, three profiles, fourteen original-engine assessments, three instructor assignments and one completed crew session. Asha's curriculum-derived baselines, guided practice and reserved evaluation are linked through actual saved records. Biren retains a separate legacy recognition cohort; Chitra remains unassessed. Calendar placement and all participant decisions are explicitly synthetic.

## Live independent exercise

In the instructor workspace, generate/approve/publish/assign a new objective candidate with explicit trainee scope. Select the trainee identity, recover the assignment after an offline reload, and start it. Wait for the actual observation paragraph to be presented, record its reference, then acknowledge the contact and submit evidence/classification/confidence/fictional report. AAR shows the canonical ledger, original score, EvidenceMind feedback and per-competency eligibility. Guided practice shows generic process guidance; independent stages show no guidance or answer key.

The browser suite performs this workflow and a separate fully offline baseline→practice→reserved-evaluation→progress→reload journey. The saved demo itself executes the continuous curriculum-to-progress chain; it does not inject score or competency constants.

## Backup and guarded reset

Use Backups & Transfer to export a complete plaintext backup and inspect it before restoration. Restore is atomic, insert-only and validates identities, policy/scenario snapshots and source references. SHA-256 detects corruption; it is neither encryption nor a signature. Profile-only transfer uses the same adaptive source/stage/reservation checks.

Return to Unrestricted local demo → Synthetic Demo → **Preview demo reset**, inspect counts, type `RESET DEMO`, then **Reset synthetic demo only**. Reset refuses outside references, extra identities, edited/additional authored scenarios, an active crew host or concurrent data changes. Genuine records are preserved. Export any demo work you want to retain before attempting reset.

Local identities are not secure authentication; browser/OS access lies outside the supported workflow boundary. Sensors, groups, scripted participants and illustrative policies require institutional/empirical validation before broader claims. VR, LAN synchronization, native executable packaging and fleet-wide hardware qualification are not delivered.
